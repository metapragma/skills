# Phase boundaries

Choose how to continue when a meaningful chunk of work ends. Prefer a completed
boundary, but an interruption can require preserving partial work. No universal
token threshold determines when a session becomes unreliable.

## Options

1. **Continue** when the existing context is useful and the session can support
   the next task. Preserve decisions in their normal artifacts as they settle.
2. **Start fresh** when the next task is unrelated or a durable ticket contains
   what it needs. First account for pending work and required context; do not
   discard unresolved decisions or assume the runtime retains a recoverable chat.
3. **Handoff** when another session, person, directory, or harness needs to resume.
   Use the handoff skill for work state, verification, authorization, and next
   actions. A summary may omit details, so link the underlying artifacts.
4. **Delegate** only when a bounded task benefits from independent work and
   delegation is available and authorized. Supply the needed source context;
   preserve the primary session for decisions and synthesis.
5. **Compact** only through facilities actually supported by the runtime.
   Preserve the active task, constraints, decisions, current evidence, and
   unresolved work. Do not claim that writing a summary edits conversation
   history or that slash commands exist in every harness.

## Resume safely

Check the actual checkout and relevant files against the recorded state.
Distinguish accepted decisions from suggestions, and observed verification
from intended checks. Re-read source when the summary is incomplete or stale.
Follow the handoff's resume checklist when one exists; a fresh session is not
permission to repeat external actions or expand the task.

These are options, not mandatory phase transitions. Choose the smallest
interruption that preserves correctness and the user's intent.
